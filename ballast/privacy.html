Ballast Privacy Policy

Ballast reports on the attachments across your Confluence site — what is largest, oldest, duplicated, and what nothing appears to reference. It runs entirely inside your own Atlassian cloud environment, reads content bodies only to extract embedded file references, and holds no write scope at all.

§ 01

Summary

Ballast (“the App”) is an Atlassian Forge app that participates in Atlassian's Runs on Atlassian program. It runs entirely inside your Atlassian cloud environment. It does not send your data to Slate's servers or to any third party — there are no external servers, no analytics calls, and no data egress.

The App is read-only: it reports on your attachments; it never deletes, moves or modifies one, and the manifest declares no write scope with which it could.

§ 02

Data we access

The App reads only what an attachment audit needs, using the granted Atlassian scopes — all read-only, in-tenant, on your behalf:

read:attachment:confluence Attachment metadata: file id, name, media type, size in bytes, creation date, and which content it hangs off. The App does not download attachment contents.
read:page:confluence Page bodies, read only to find embedded file references.
read:blogpost:confluence Blog-post bodies, for the same reason.
read:comment:confluence Footer and inline comment bodies. A file embedded only in a comment is genuinely in use, and a scan that skipped comments would wrongly report it as unreferenced.
read:custom-content:confluence Custom content bodies — other apps store references here.
read:space:confluence Spaces, and the rendered space description: a space header image is referenced there and nowhere else.
storage:app Store the report snapshot.

For every body it reads, the App extracts the file ids that body embeds and discards the body. It does not store, index or transmit the text of your content.

§ 03

Data we store

The App stores one report snapshot in Atlassian-hosted Forge storage, which lives inside your Atlassian cloud environment and inherits its data-residency region. The snapshot contains only what the report shows:

attachment metadata — file id, file name, media type, size and creation date; the id of the page, blog post or custom content each file hangs off; whether a reference to each file was found, and in how many surfaces the scan looked; duplicate groupings; and totals per media type.

Page bodies are not stored. No attachment content is ever read or stored. Each scan replaces the previous snapshot rather than accumulating history.

§ 04

Personal data

The App does not store display names, email addresses or account identifiers. An attachment's uploader is not recorded, so no report:personal-data reporting obligation arises and the scope is not requested.

One thing worth stating plainly: file names are user-supplied text and can contain personal data. payroll-2026-jane-doe.xlsx is a real thing people upload. The App stores file names because a storage report without them is unusable, and it shows them to Confluence site administrators, who can already see them in Confluence itself. It does not transmit them anywhere.

§ 05

Data we do NOT collect

We do not sell, rent, or share your data. We do not use it for advertising or to train machine-learning models. We do not receive a copy of it — it never leaves your Atlassian tenant. We do not read your page content beyond extracting embedded file references, and we never modify or delete an attachment.

§ 06

Sub-processors

None beyond Atlassian itself (the platform hosting the App). Because the App runs on Atlassian with no egress, no additional sub-processors are involved.

§ 07

Security

The App inherits Atlassian's platform security controls, including SOC 2 Type II and ISO/IEC 27001, and Atlassian's data-residency options. The report is an administrative surface, available to your Confluence site administrators.

No write scope. The manifest declares read scopes only. There is no delete button in the App, and no permission behind one. Ballast could not remove an attachment if a bug tried to.

§ 08

Data retention and deletion

The report snapshot is stored only while the App is installed. Uninstalling the App removes the App's stored data from your Atlassian environment.

§ 09

Children

The App is a business tool and is not directed to children under 16.
