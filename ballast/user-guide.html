Ballast User Guide

Confluence Cloud shows attachments one page at a time, so nobody can answer “what is our storage actually going on?”. Ballast answers it for the whole site in one report — and is careful about the one question it cannot answer with certainty. It is read-only: there is no delete button, and no write scope in the manifest.

In the report

01

Run a scan

Go to Confluence Settings → Apps → Ballast — Attachment Audit and click Run scan. The scan runs in the background, off the request clock, so large sites don't time out; the report refreshes when it finishes. Ballast also re-scans weekly.

A scan does two passes: it lists every attachment on the site, then reads every surface that can embed a file — pages, blog posts, footer and inline comments, custom content, and space descriptions.

02

Read the certain half

These four come from attachment metadata alone, so they are true regardless of what the reference pass managed to read:

Largest files
With the page each one hangs off. Click through to see it in context. This is nearly always where the recoverable space is.
Oldest files
Where to look first, not a delete list. A policy PDF from 2019 is old and entirely in use. Old and large together is a far better signal than either alone.
By type
Where the space actually went. Usually the surprise is video or design exports, not documents — chasing image counts is mostly wasted effort.
Possible duplicates
Same file name and same byte size, with what keeping one copy would free. Candidates, not proof: the API exposes no checksum, so two genuinely different files of identical name and size would appear here too.
03

Read the uncertain half carefully

The No reference found list is the one everybody wants, and the one to treat with care. Ballast lists a file here when none of the surfaces it scanned embeds that file. It does not call the file orphaned or unused, because that cannot be proven:

Whiteboards and databases cannot be read
Both can embed files, and neither can be read through the Confluence API at all — the endpoints return an error. A file used only in a whiteboard will appear on this list.
Future content types are invisible
Any content type Atlassian adds later is invisible to this app until it learns about it.

So the report prints, every time, the surfaces it searched and the surfaces it could not. Read that line before deleting anything. The right way to use the list is as a shortlist to check, not as a work queue.

If the list looks impossibly long, check the coverage line first. A scan that failed to read pages will report every file as unreferenced — and the coverage line is what tells you that is what happened, rather than letting you believe the number.

04

Export the CSV

Export CSV gives you every file in the report — id, file id, name, type, size, date, container, whether a reference was found, and which duplicate group it belongs to. The first rows carry the scan date and the same coverage sentence, because the file will outlive the screen it came from and whoever opens it next needs to know what was searched.

The CSV is UTF-8 with a BOM, so it opens cleanly in Excel and Google Sheets.

Free vs paid

Free forever

The full report — every list above — at any team size.

Paid — free up to 10 users

CSV export. Atlassian's free tier for teams of 10 or fewer counts as an active licence, so small teams get everything. Above 10 users export needs an active license; an admin can start a free trial under Settings → Apps → Manage apps.

—

What Ballast does not do

It never deletes, moves or modifies a file
There is no button, and the manifest declares no write scope, so it could not if it tried.
It does not promise to reclaim storage
It reports what removing duplicate copies would free; freeing it is your decision and your action.
It does not prove a file is unused
See section 03. If a tool tells you it can, ask which surfaces it read.
—

Privacy

Ballast runs on Atlassian: no external servers, no egress. It stores one report snapshot in Forge storage (file names, sizes, types, dates and the ids of the pages they hang off). It reads no page text beyond looking for embedded file references, and keeps none. The full Ballast Privacy Policy is linked from the app's Marketplace listing and from the Slate documentation index.
