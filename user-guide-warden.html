Warden User Guide

Confluence Cloud gives you no way to see, across every space, which pages are restricted and to whom. Warden inventories every restricted page in one report and flags the risky restrictions nobody else catches, then lets you export a compliance snapshot. It is read-only: Warden never changes your restrictions.

Access Audit report

Every view/edit-restricted page across the site, direct versus inherited, plus red flags — and what changed since the previous scan.

Confluence Settings → Apps → Warden

Red flags

Restrictions that quietly break governance: deactivated user, empty group, orphaned principal — plus stranded pages whose entire audience is now dead.

01

Run a scan

Go to Confluence Settings → Apps → Warden — Access Audit and click Run scan. The scan runs in the background, off the request clock, so large sites don't time out; the report refreshes automatically when it finishes. Warden also re-scans daily to keep the snapshot fresh.

The scan walks every space, finds every view/edit-restricted page, and resolves the users and groups those restrictions name.

02

Read the report

Red flags come first — the restrictions that silently break access governance:

Deactivated user
A page restricted to a user who has been deactivated.
Empty group
A restriction pointing at a group with no members.
Orphaned principal
The user or group named in the restriction no longer exists.
No live viewer / No live editor
The page-level consequence: every user and group granted view (or edit) is deactivated, empty or deleted, so the page's intended audience is locked out and only site admins can still reach it. This is the one to fix first — a stranded view restriction also strands every page that inherits it.

Since last scan — every scan is compared with the one before it. A banner above the table says how many red flags are new and how many were resolved, and each new finding carries a New marker. From the second scan onwards you read a diff, not the whole inventory again.

Restricted pages lists every restricted page, who can view or edit it, and whether the restriction is set directly on the page or inherited from an ancestor, naming the ancestor it came from. Clicking a page opens it in a new tab so you can fix the restriction in Confluence.

Partial scan. Very large sites are scanned up to a page cap; if it is hit, the report is flagged as partial — a snapshot of the first pages scanned.

03

Export the compliance snapshot

Use Export inventory CSV for all restricted pages, or Export red-flags CSV for just the findings, to get an auditor-ready snapshot. The CSV is UTF-8 with a BOM, so it opens cleanly in Excel and Google Sheets.

▪

What Warden does not do, by design

It is not a historical change-log
It is a point-in-time snapshot. A Forge app cannot reconstruct who changed a restriction and when.
It is not auto-remediation
It reports and flags; it never changes your restrictions and does not “guarantee compliance”. You act on the evidence.
▪

Troubleshooting

Report is empty
Run a scan first, and remember Warden only lists restricted pages — a site with no restrictions has nothing to flag. Page restrictions are a Standard-and-above Confluence feature.
Export shows an upgrade prompt
You are above the free tier without an active license. Start a trial as above; viewing the report stays free.
A “Partial” badge appears
A very large site hit the page cap; the snapshot covers the first pages scanned.
A deactivated user isn't flagged
The deactivated-user signal is best-effort under Runs-on-Atlassian. The empty-group and orphan flags are exact.
A page shows atomic flags but no “No live viewer”
That is correct: at least one live user or group can still see it, so it is not stranded. “No live viewer/editor” fires only when every grantee is dead.
▪

Data & privacy

Warden Runs on Atlassian — no external servers, no egress. Every scope is read-only and in-tenant; there is no write scope in the manifest, so Warden cannot modify a restriction. The snapshot lives in Forge storage inside your tenant.
